# subconscious - цели и функции

## Что это

subconscious - готовое ПО для автономных нейросетевых агентов, работающих
в инфраструктуре. Не фреймворк. Не SaaS. Один пользователь на инстанс,
несколько хостов, произвольные источники памяти.

Никита и Эльза - частный случай. Общий случай: N агентов, M хостов,
любая инфраструктура.

## Картина финала

Агент:

- работает в инфраструктуре, возможно на разных хостах;
- накапливает знания о своём окружении;
- иногда общается с человеком для корректировки целей и подтверждений;
- автономен в:
  - исследовании (read-only везде);
  - записи в свои файлы и туда, где есть доступ;
  - своей памяти.

## Четыре зоны

```
subconscious-core/
├── core/       ← суть: данные и состояние (память, ledger, budget, session)
├── cortex/     ← интерфейсы: chat, event, a2a, cli
├── thalamus/   ← связки: backends, mcp, router, фильтры
└── subcortex/  ← суть: фоновое мышление (planner, executor, reflector, assessor)
```

- **core** - данные. Не логика.
- **cortex** - интерфейсы наружу. Чат - один из них, не суть проекта.
- **thalamus** - связки с внешним миром (LLM, MCP-инструменты).
- **subcortex** - логика автономии. Это главная фича.

## Цели проекта

| № | Цель | Проверка |
|---|---|---|
| G1 | Агент работает в инфраструктуре, не только в чате | Фон выполняется, реагирует на события, вызывает MCP |
| G2 | Параллельная работа нескольких агентов и целей | Worker pool, независимые ledger'ы |
| G3 | Накопление знаний | Персистентный ledger, KG, наблюдения |
| G4 | Человек в цикле | Канал «предложение → одобрение» |
| G5 | Автономность в границах | Read-only для исследования, изоляция канона |
| G6 | Гибкая настройка без правки кода | Layered configs и prompts |
| G7 | Совместимость с A2A | Agent Card, Task, Message, Artifact |
| G8 | Развёртывание одним человеком | install script, документированные дефолты |

## Принципы

- **Unix way.** Один процесс - одна зона. Конфиг через env и файлы.
- **Готовое ПО.** Установил, настроил, работает.
- **Layered override.** `repo → /etc/subconscious → ~/.config/subconscious → env`.
- **Изоляция агента.** Каждый агент пишет только в свой state. Общий канон - через явный интерфейс.
- **Человек в цикле.** Агент предлагает, человек одобряет.
- **Прозрачность.** Всё видно в journal и ledger. Никаких скрытых решений.
- **Совместимость по стандартам.** A2A для агентов, MCP для инструментов, OpenAPI для HTTP.
- **Пользователь решает.** Механизмы даются, политика - за пользователем.

## Non-goals

- Не SaaS. Установка на свою инфраструктуру.
- Не UI-first. CLI + HTTP + jq - базовые интерфейсы.
- Не marketplace. Нет реестра плагинов от сообщества.
- Не enterprise. Нет multi-tenancy, SSO, RBAC.
- Не копировать Soothe. Совместимость через A2A, не через форк.
- Не переписывать lazy-mcp на Python без нужды.

## Три уровня совместимости

- **A2A** - между агентами (нашим и чужими).
- **MCP** - между агентом и инструментами.
- **Внутренний протокол** - внутри агента (planner → executor → assessor).

Не смешивать. Три независимых слоя.

## Память: стратегия

Вариант C - гибрид:

- **KG** - свой, SQLite, ~200 строк. Триплы с valid_from / valid_to.
- **Vector store** - `sqlite-vec` (уже в requirements).
- **Identity** - свой `identity.txt`, свой загрузчик.
- **Layers** - своя сборка L0 / L1 / L1.5.
- **Mempalace** - переезжает за MCP: только чтение старых данных (3483 drawer'а).

Своя память становится обязательной. Mempalace - опциональным источником.
